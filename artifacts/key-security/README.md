# Agent Key 安全验收

验收基线：upstream main `4b3c0d8`（已包含 #10 医疗平台、#14 CI、#17 用户层级保护）。

自动验证：`npm run typecheck`、`npm run build`、`npm test`，47/47 通过。仅测试临时 SQLite 和上传目录。新增回归涵盖 scopes/归属/期限/撤销/轮换、旧明文和 hash-only 迁移、稳定主密钥重启解密、缺配置保持访问与轮换 503、错误主密钥启动失败、备份恢复、files 与 Markdown/AI 下载、管理员普通 Key 的资源隔离、可信 HTTPS 代理 Secure Cookie、伪造转发头、共享 NAT 正常注册/登录与单账号限流。原有医疗流程与用户层级回归保留。

浏览器验证使用 cua_repl，在 1440×1000 和 390×844 视口检查普通/分类标签技能。确认普通 Key 展示权限及到期、7 天只读轮换后移除写权限、复制文案带权限/期限；管理技能显式创建，复制内容仅为 taxonomy 范围且带到期时间。390px 页面 document.scrollWidth=390，无横向溢出。截图在本目录，均来自无真实业务数据的临时账号；截图中的测试 Key 已在验收后撤销，测试服务已停止。截图是桌面浏览器视口模拟，未做物理手机验收。

主机没有 127.0.0.8 回环别名，绑定返回 EADDRNOTAVAIL，连接超时，系统禁止无密码添加别名。因此界面验收采用独立 `agent-key-security.localhost:5188`（API 3088、loopback），与其他实例隔离 Cookie，未修改系统网络配置或其他会话服务。

机械设计检查报告两项既有页面警告（提交页标签 border-b-2、首页灰字/橙底），不属于此次 Key 表单调整；保留既有视觉设计。

运维条件：发布前配置稳定主密钥、备份旧 DB，并同步生产单元的 TRUSTED_PROXY_IPS=127.0.0.1 或在受保护运行环境明确设置；单元 EnvironmentFile 会覆写默认值。未合并或部署本分支。进程内限流重启会清空，多实例需入口共享限流。旧 Key 不自动变成受限 Key，仍需用户登录后轮换。不要直接回退到忽略 scopes/期限的旧二进制。完整步骤见 ops/AUTH-SECURITY.md。
